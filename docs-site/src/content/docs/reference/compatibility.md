---
title: Compatibility and support
description: Version boundaries, tested configurations, change policy and security support.
---

DotBoxD is pre-1.0. Package versions use SemVer; prerelease builds are integration snapshots, not
an indefinite compatibility promise. Breaking public changes require a reviewed API/binary baseline
change and migration notes. After 1.0, breaking public API, wire or package-format changes require a
new major version. Additive optional fields must preserve their documented defaults.

## Independent version boundaries

| Boundary | Identifier | Change rule |
| --- | --- | --- |
| Connection/wire | `RpcProtocolOffer.CurrentVersion` (1) | Change framing or message meaning only under a new negotiated wire version. |
| Optional protocol behavior | `SupportedFeatures` / `RequiredFeatures` | Allocate bits by agreement between applications; there are currently no library-defined feature bits. Unknown optional bits are ignored; unknown required bits reject the connection. |
| Codec | `CodecId` (1 for DotBoxD MessagePack) | A different serialization format needs a different application-assigned ID. |
| RPC contracts | `RpcContractManifest` format 1 and SHA-256 fingerprint | Additive members may be compatible according to the manifest diff; removing/changing signatures is breaking. Exact fingerprint negotiation intentionally requires equality. |
| Kernel language / compiled ABI | `SandboxLanguage.CurrentVersion`, compiler/type-system/effect-analysis/canonicalizer versions and verifier/runtime-facade identities | Persisted compiled artifacts are caches, not portable plugins; existing cache verification rejects stale identities. Recompile from validated IR. |
| Plugin JSON | `schemas/v1/dotboxd-plugin-package.schema.json` | Existing package format remains usable without the artifact envelope. |
| Signed artifact | `PluginArtifact.CurrentSchemaVersion` (1) | Unknown schema versions fail closed before package parsing. |
| Replay document | `ExecutionTrace.CurrentFormatVersion` (1) | Unknown formats reject; runtime metadata is retained so cross-version replay can identify drift. |

Package SemVer is separate from these identifiers: a package patch does not silently reinterpret an
existing wire frame, signature or trace. Changing an existing feature bit's meaning is breaking.

## Optional negotiation and legacy peers

The previous release used raw frames: little-endian total length (4), message ID (4), message type
(1), then the body. These exact bytes remain the frame ABI for connection version 1. Golden tests
pin request/response/error bytes generated by the published `0.1.0-ci.5510` packages, the old cancel
frame and the new preamble, check bidirectional old/new framing compatibility,
and exercise older/newer version offers. There is no previous negotiated protocol to pretend to test.
Future wire versions must retain tests against the last supported version's implementation/fixtures.

Both endpoints explicitly opt into `RpcProtocolNegotiation.ExchangeAsync` **before constructing a
channel or starting an RPC receive loop**. It exchanges a fixed 68-byte little-endian preamble:

| Offset | Field |
| --- | --- |
| 0 | `DBX1` magic (4 bytes) |
| 4 | Preamble format, UInt16 = 1 |
| 6, 8 | Minimum and maximum wire version, UInt16 each |
| 10 | Reserved UInt16, must be zero |
| 12 | Codec ID, UInt32 |
| 16, 24 | Supported and required feature masks, UInt64 each |
| 32 | Maximum total frame size, Int32 |
| 36 | Contract SHA-256 bytes, all zero when omitted |

The highest common version, feature intersection and smaller frame limit win. Both directions must
support every required feature. If either endpoint specifies a fingerprint, both must specify the
same fingerprint. Apply `agreement.MaximumFrameSize` to `StreamConnection`; the low-level exchange
leaves channel construction and stream ownership with the caller. `Encode`, `Decode` and `Negotiate`
are public for hosts that own their readiness transport. A test hand-writes the exchange and gets
the same channel behavior as the helper.

Legacy connections must be configured explicitly on **both** ends by omitting the preamble. Never
retry a failed negotiation as legacy: this would allow downgrade attacks. The preamble's magic is
an invalid legacy frame length, so a legacy receiver rejects it before processing RPC. Negotiation
is not authentication; use [authenticated transport](/security/transport/).

## Supported configurations and ownership

The repository owner maintains Linux and Windows Release CI. Services/channels target netstandard2.1;
package consumer checks cover the configured .NET runtimes, while Kernels/Hosting/Pushdown require
.NET 10. NativeAOT Services + MessagePack + TCP has a maintained Linux publish/run smoke.

Unity/IL2CPP is a conditional integration path, not a certified Unity version matrix. The application
owner must pin Unity and MessagePack, generate/static-root DTO formatters, and run its own IL2CPP
batch build. Browser/WebGL networking requires an application-owned transport. macOS and Mono do
not currently have the same required CI coverage; compatibility is best effort, not a tested support
promise. See the [Unity guide](/channels/unity-integration/) for the boundary.

## Deprecation, security and end of support

Before 1.0, supported fixes target the current main/release line; old CI snapshots receive no
backports. After 1.0, public APIs marked obsolete remain for at least one minor release and 90 days
before removal in a major release. Security fixes may require immediate restriction of unsafe
behavior, with a changelog entry and migration guidance.

The current stable major receives security fixes. The previous stable major receives critical
security fixes for 90 days after a new major release, provided its .NET runtime remains supported by
its vendor. End-of-support notices belong in the changelog and release notes; after that date users
must upgrade. Report vulnerabilities through the repository's security policy. No paid response-time
or universal Unity compatibility guarantee is implied.

The readable source baseline and SDK package validation both run before packing publishable
artifacts. Because no stable package exists yet, the binary baseline is pinned in
`eng/package-compatibility.props` to `0.1.0-ci.5510`; it must move to the last stable release at 1.0.
